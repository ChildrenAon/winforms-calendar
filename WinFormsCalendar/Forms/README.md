# Forms — 창(폼) 모음

프로그램의 창 하나가 파일 하나(세트)입니다. 새 기능의 창은 이 폴더에 만듭니다.

## 어느 파일을 열어야 하나

| 창 | **열어서 고칠 파일** | 하는 일 | 열리는 곳 | 브랜치 |
|---|---|---|---|---|
| 일정 등록·수정 | `ScheduleForm.cs` | 제목, 시간·분, 메모, 카테고리 색, 첨부 파일, D-day 입력 | 메인 화면의 [추가]/[수정] | `feature/schedule` |
| 일정 검색 | `SearchForm.cs` | 키워드로 일정 찾기 | 메인 화면의 [검색] | `feature/search` |
| 타임캡슐 | `TimeCapsuleForm.cs` | 날짜와 메시지를 저장하고, 그 날짜가 되면 팝업 | 메인 화면의 [타임캡슐], 날짜가 되었을 때 | `feature/time-capsule` |
| 잔디 기록 | `GrassForm.cs` | 날짜별 활동과 시간 기록 (칸 색은 메인 화면에서 칠함) | 메인 화면의 [잔디] | `feature/grass` |
| 미니 위젯 | `MiniWidgetForm.cs` | 달력을 작게 화면 구석에 항상 위에 표시 | 메인 화면의 [미니 모드] | `feature/mini-widget` |

## 창 하나에 파일이 3개인 이유

예를 들어 `ScheduleForm`은 아래 세 파일이 한 세트입니다.

| 파일 | 역할 | 직접 고치나요? |
|---|---|---|
| `ScheduleForm.cs` | 버튼을 눌렀을 때 하는 동작 같은 **직접 쓰는 코드** | **네, 여기서 작업합니다** |
| `ScheduleForm.Designer.cs` | 버튼·입력칸을 어디에 놓았는지 Visual Studio가 **자동으로 만든 코드** | 아니요 |
| `ScheduleForm.resx` | 폼에 딸린 리소스(이미지, 문자열) | 아니요 |

- 화면을 꾸밀 때는 `ScheduleForm.cs`를 더블클릭해서 나오는 **디자이너 화면**에서 컨트롤을 끌어다 놓습니다. 그러면 `.Designer.cs`와 `.resx`는 알아서 바뀌고, 그 변경이 커밋에 같이 올라가는 것은 정상입니다.
- 코드 편집기에서 `.Designer.cs`를 직접 고치면 디자이너가 깨질 수 있으니 하지 않습니다.

## 지켜 주세요

- 파일 맨 위 주석의 `하는 일`, `참고 수업`, `담당`을 최신으로 유지합니다.
- 네임스페이스는 항상 `WinFormsCalendar`입니다.
- 새 창을 추가하면 [작업 가이드](../../docs/작업가이드.md)의 표에도 한 줄 추가합니다.
