# 설계 (초안)

> 팀 합의 전의 초안입니다. 확정되면 이 문서를 고치고 "초안" 표시를 지웁니다.

## 달력 칸의 색

- 칸 **배경색**은 잔디 심기가 사용합니다. (활동 시간이 길수록 진해짐)
- 일정의 카테고리 색은 칸 안의 작은 표시(점이나 글자색)로 보여줍니다.

## 데이터

| 종류 | 내용 |
|---|---|
| 일정 | 날짜, 시작 시간·분, 제목, 메모, 카테고리, 첨부 파일 경로, D-day 표시 여부 |
| 타임캡슐 | 날짜, 메시지 |
| 잔디 기록 | 날짜, 활동명, 시간(분) |

- D-day는 별도 항목이 아니라 일정의 속성으로 둡니다.
- 타임캡슐은 달력에 표시하지 않고, 해당 날짜가 되면 앱 시작 시와 `Timer`로 확인해서 알려줍니다.

## 저장 방식

- 한 줄에 한 항목을 `|`로 구분해 텍스트 파일로 저장합니다. 맨 앞 글자로 종류를 구분합니다.
- 위치는 실행 폴더의 `data/`, 인코딩은 UTF-8, 변경할 때마다 즉시 저장합니다.
- 첨부 파일은 복사하지 않고 경로만 저장합니다.

## 화면 구성 (메인)

- 상단: 년/월, 이전·다음 달, 오늘, 검색
- 중앙: 7×6 날짜 칸
- 하단/우측: 선택한 날짜의 일정 목록, 추가·수정·삭제 버튼, D-day 영역
- 칸 클릭은 날짜 선택, 더블클릭은 일정 추가

## 폼 사이의 데이터 전달

- 메인 폼이 일정 목록을 갖고, 일정 입력 폼을 열 때 생성자로 넘깁니다. (수업 5주차 실습과 같은 방식)

## 구현 순서

1. 뼈대 + 달력 칸 + 오늘 표시
2. 일정 등록·수정·삭제 (메모리에서만)
3. 저장·불러오기
4. 시간, 카테고리 색, 파일 첨부
5. 검색, D-day
6. 타임캡슐, 잔디, 미니 위젯
