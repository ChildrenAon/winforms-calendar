# 작업 가이드

"내 기능은 어떤 파일에서 작업하지?"를 한눈에 보기 위한 문서입니다. 파일은 이미 만들어져 있고 `.csproj`에도 등록돼 있으니, **자기 파일만 열어서 채우면 됩니다.**

## 기능 → 파일 → 브랜치

구분은 계획 발표 기준입니다. **필수 → 추가 순서로 먼저 만들고, 확장은 여유가 되면 만듭니다.** 결과물 발표의 시연은 1분 내외 영상으로 하므로, 필수·추가 기능을 안정적으로 만드는 것이 우선입니다.

| 구분 | 기능 | 작업할 파일 | 브랜치 이름 | 담당 |
|---|---|---|---|---|
| 필수 | 달력 틀, 오늘 표시, 월 이동 | `MainForm.cs` | `feature/calendar` | ChildrenAon |
| 필수 | 일정 등록·수정·삭제 | `Forms/ScheduleForm.cs`, `Models/Schedule.cs` | `feature/schedule` | ChildrenAon |
| 추가 | 일정의 시간/분 설정, 파일 첨부 | `Forms/ScheduleForm.cs` | `feature/schedule` | ChildrenAon |
| 추가 | 타임캡슐 메시지 | `Forms/TimeCapsuleForm.cs` | `feature/time-capsule` | WhelkMono |
| 확장 | 일정의 카테고리 색, D-day | `Forms/ScheduleForm.cs` (D-day 표시는 `MainForm.cs`) | `feature/schedule` | ChildrenAon |
| 확장 | 저장·불러오기 | `Data/DataStore.cs` | `feature/save-load` | ChildrenAon |
| 확장 | 키워드 검색 | `Forms/SearchForm.cs` | `feature/search` | WhelkMono |
| 확장 | 잔디 심기 | `Forms/GrassForm.cs` (칸 색 칠하기는 `MainForm.cs`) | `feature/grass` | WhelkMono |
| 확장 | 미니 위젯 모드 | `Forms/MiniWidgetForm.cs` | `feature/mini-widget` | 미정 (달력이 만들어진 뒤 여유가 되면) |

담당은 GitHub 아이디입니다. 바뀌면 위 표와 각 파일 맨 위 주석의 `담당`을 같이 고칩니다. **담당은 이 표에서만 관리합니다.**

## 폴더 설명

| 폴더 | 들어가는 것 |
|---|---|
| `WinFormsCalendar/` (바로 아래) | `Program.cs`, 메인 화면 `MainForm` |
| `Forms/` | 창(폼) 하나당 파일 하나. 새 창은 여기에 만든다 |
| `Models/` | 데이터 모양을 정의하는 클래스 (예: `Schedule`) |
| `Data/` | 파일 저장·불러오기 같은 데이터 처리 |
| `docs/` | 기능 명세, 설계, 발표 분량, 이 문서 |

## 창 하나에 파일이 3개인 이유

`Forms/` 폴더를 열면 `ScheduleForm.cs`, `ScheduleForm.Designer.cs`, `ScheduleForm.resx`처럼 같은 이름이 세 개씩 보입니다. 한 창의 세트입니다.

- `XxxForm.cs` : 직접 쓰는 코드. **여기서만 작업합니다.**
- `XxxForm.Designer.cs` : 컨트롤 배치를 Visual Studio가 자동으로 만든 코드. 직접 고치지 않습니다.
- `XxxForm.resx` : 폼에 딸린 리소스. 건드리지 않습니다.

디자이너 화면에서 컨트롤을 옮기면 `.Designer.cs`와 `.resx`가 자동으로 바뀌고, 그 변경이 같이 올라가는 것은 정상입니다. 자세한 설명은 [Forms/README.md](../WinFormsCalendar/Forms/README.md)에 있습니다.

## 작업 규칙

1. **기능마다 브랜치를 따로 만들어 작업합니다.** 이름은 위 표를 따릅니다. 끝나면 Pull Request를 올리고, `ChildrenAon`이 확인한 뒤 `main`에 합칩니다. 작업 도구는 각자 편한 것을 씁니다.
2. **`MainForm.cs`는 `ChildrenAon`이 담당합니다.** 다른 분이 만든 창을 메인 화면에서 여는 코드는, 해당 창이 완성되면 한 줄만 추가하는 방식으로 하고 미리 알려 주세요. 같은 파일을 동시에 고치면 충돌이 납니다.
3. **네임스페이스는 항상 `WinFormsCalendar`입니다.** Visual Studio가 새 파일을 만들 때 `WinFormsCalendar.Forms`처럼 폴더 이름을 붙이는 경우가 있는데, 지우고 `WinFormsCalendar`로 맞춥니다.
4. **파일 맨 위 주석을 유지합니다.** 하는 일과 참고한 수업 주차를 갱신해 두면 발표 준비에 그대로 쓸 수 있습니다. 수업에 없는 문법을 썼다면 `참고 수업`에 적어 둡니다.
5. **한글 주석**을 충분히 답니다. 컨트롤 이름은 `btnAdd`, `lblDate`처럼 역할이 보이게 짓습니다.
6. 새 파일을 추가하면 `WinFormsCalendar.csproj`가 바뀝니다. 충돌이 나면 양쪽에 추가된 줄을 **둘 다 남기면** 됩니다.

## 새 창을 더 만들어야 할 때

`Forms` 폴더를 우클릭 → 추가 → 새 항목 → Windows Forms → 폼(Windows Forms)을 고르고 이름을 `XxxForm`으로 짓습니다. 만들어진 뒤 네임스페이스를 `WinFormsCalendar`로 고치고, 이 문서의 표에 한 줄을 추가합니다.

## 용어 풀이

| 용어 | 뜻 |
|---|---|
| 폼(Form) | 프로그램의 창 하나 |
| 모달 폼 | 열려 있는 동안 뒤쪽 창을 누를 수 없는 창 (예: 일정 입력 창) |
| 네임스페이스 | 코드 맨 위의 `namespace WinFormsCalendar`. 이 프로젝트에서는 항상 같은 이름을 씁니다 |
| 레포(저장소) | 프로젝트의 모든 파일과 변경 기록이 담긴 GitHub 폴더 |
| 클론 | 레포를 내 컴퓨터로 내려받는 것 |
| 커밋 | 작업한 내용을 하나의 기록으로 저장하는 것 |
| `main` | 항상 실행되는 완성본이 모이는 기본 브랜치 |
| 브랜치 | `main`을 건드리지 않고 작업하기 위한 작업용 사본. 예: `feature/search` |
| Pull Request(PR) | "내 브랜치의 작업을 `main`에 합쳐 주세요"라는 요청. 확인하고 합칩니다 |
| 담당 | 그 파일을 맡아 작업하는 사람 (GitHub 아이디) |
| N주차 | 수업 실습 N주차 예제. 파일 맨 위 `참고 수업`에서 어디를 보면 되는지 알려 줍니다 |
